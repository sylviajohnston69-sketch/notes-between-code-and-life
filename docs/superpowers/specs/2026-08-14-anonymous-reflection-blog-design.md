# 匿名技术与随想博客设计

日期：2026-08-14

## 1. 项目目标

创建一个匿名公开的个人博客，帮助作者整理技术学习、生活经历、困惑和阶段性思考。网站的首要服务对象是作者自己，同时允许陌生读者通过公开网址阅读。

成功标准：作者可以通过网页后台或本地 Markdown 两种方式写作；发布后，读者可以在电脑和手机上舒适地阅读、搜索和浏览文章；站点不暴露作者的真实身份。

## 2. 产品定位

- 内容主题：技术、随想和短篇札记。
- 写作态度：记录当前认识，不强求形成永恒结论，允许未来修正旧观点。
- 读者：以作者本人为主，也面向偶然访问的公开读者。
- 身份：使用独立笔名和匿名账号，不展示真实姓名、单位或私人联系方式。

## 3. 首版范围

首版包含：

- 首页文章列表，显示标题、日期、栏目、阅读时长和摘要。
- 文章正文页，支持常用 Markdown、图片和代码高亮。
- 技术、随想、札记三个初始栏目。
- 标签浏览和站内搜索。
- 按时间浏览文章的归档页。
- 匿名“关于”页，只说明写作缘起。
- 适配手机与桌面屏幕。
- 自定义 404 页面。
- 网页后台写作与本地 Markdown 写作。

首版不包含：

- 评论、点赞、读者注册和订阅会员。
- 访问统计、广告和第三方行为追踪。
- 多作者协作、付费内容和复杂权限系统。

## 4. 视觉与信息结构

采用“旧刊与札记”方向：暖米色纸张背景、暗红褐色标题区域、克制的衬线字体和少量旧刊装饰。页面应温暖、安静、耐读，不模仿终端界面，也不使用强烈的复古纹理影响代码与长文阅读。

顶部导航包括首页、归档、关于和搜索。首页主体显示文章列表，桌面端右侧显示搜索、栏目、标签和匿名说明；手机端侧栏移动到文章列表下方。文章页保持较窄的正文宽度，并为代码块提供清晰的等宽字体、横向滚动和语法高亮。

示例名称“在代码与生活之间”和示例副标题“一个匿名者的思想存档”仅用于搭建阶段。正式名称和笔名可在上线前替换，不影响页面结构。

## 5. 技术架构

- Astro 生成静态博客页面，减少运行时复杂度并获得快速的阅读体验。
- 每篇文章保存为仓库中的 Markdown 文件。
- Pages CMS 为同一批 Markdown 文件提供网页编辑界面，不建立独立内容数据库。
- GitHub 保存网站代码、文章和修改历史。
- Vercel 连接 GitHub；仓库更新后自动构建并部署网站。
- 首次上线使用 Vercel 提供的公开地址，自定义域名作为上线后的可选步骤。

数据流：

1. 作者在 Pages CMS 网页后台或电脑本地编辑 Markdown。
2. 内容保存到 GitHub 仓库。
3. Vercel 拉取最新版本并运行构建检查。
4. 构建成功后更新公开网站；失败时保留上一个正常版本。

## 6. 内容模型

每篇文章至少包含：

- `title`：文章标题。
- `date`：发布日期。
- `description`：首页和搜索结果使用的摘要。
- `category`：技术、随想或札记。
- `tags`：零个或多个主题标签。
- `draft`：是否为草稿。
- 正文：Markdown 内容。

标记为草稿的文章不进入公开页面、归档、栏目、标签或搜索结果。阅读时长根据正文自动计算，不要求作者手工填写。

## 7. 发布与错误处理

- 缺少标题、日期、摘要、栏目或草稿状态时，构建失败并阻止错误版本上线。
- 日期或字段类型不合法时给出明确的构建错误。
- Pages CMS 和本地写作使用同一内容格式，避免两套内容相互覆盖或转换失真。
- 无效文章地址显示站内 404 页面，并提供返回首页入口。
- 搜索无结果时显示友好提示，不显示空白页面。
- 图片缺失时构建检查应尽早暴露问题；图片必须填写替代文字以帮助无障碍阅读。

## 8. 匿名与隐私边界

- 注册独立的 GitHub 账号，使用笔名、独立邮箱和匿名头像。
- Git 提交使用匿名公开邮箱，不提交真实姓名或私人邮箱。
- 不在关于页、文章元数据和站点页脚展示真实身份信息。
- 发布图片前移除 EXIF 定位信息；检查截图中的用户名、单位、文件路径、通知和浏览器账号。
- 首版不接入统计或第三方追踪脚本，减少额外的数据收集。
- 文章内容仍由作者在发布前进行人工隐私检查；技术手段无法判断正文是否间接暴露身份。

## 9. 验证方案

每次重要修改至少完成：

- 运行生产构建，确认内容格式和页面生成成功。
- 检查首页、文章、归档、栏目、标签、搜索、关于和 404 页面。
- 验证草稿不会出现在任何公开列表或搜索结果中。
- 检查一篇技术文章的代码高亮、长代码横向滚动和移动端显示。
- 检查一篇长随想的字体、行距、段落宽度和目录阅读体验。
- 在桌面和常见手机宽度下检查导航及侧栏布局。
- 部署后访问公开地址，确认 Vercel 的线上版本与本地预览一致。

## 10. 实施顺序

1. 创建 Astro 项目和内容结构。
2. 完成旧刊札记风格的页面与响应式布局。
3. 加入文章、栏目、标签、归档、搜索和草稿过滤。
4. 配置 Pages CMS。
5. 建立匿名 GitHub 仓库并推送项目。
6. 连接 Vercel，完成首次公开部署。
7. 进行线上验证，并讲解以后写作和更新的完整流程。
